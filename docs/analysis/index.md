# Аналитика решения

Раздел описывает ADO Board Task Filter 1.0.0 глазами системного аналитика: какую проблему решает расширение, какие требования выполняет, как устроено и как обменивается данными с Azure DevOps Server. Каждое требование покрыто проверкой на стенде.

| Документ | Что внутри |
|---|---|
| [Требования](requirements.md) | Контекст и проблема, цели, границы, роли, 12 пользовательских историй с критериями приёмки, сценарий использования, 24 функциональных и 10 нефункциональных требований, ограничения и риски |
| [Процессы AS-IS и TO-BE](processes.md) | BPMN 2.0: подготовка к обсуждению работы участника до и после внедрения |
| [Архитектура](architecture.md) | Компоненты, подключение сервера, ключевые решения и их причины |
| [Интеграция с REST API](integration.md) | Запросы к Azure DevOps Server, примеры JSON, WIQL, обработка ошибок, диаграмма последовательности |
| [Модель данных](data-model.md) | ER-диаграмма, правила участия, настройки и локальное состояние |
| [Поведение панели](behavior.md) | Диаграмма состояний, алгоритм решения по карточке, управление с клавиатуры |
| [Проверка](testing.md) | Стенд, 48 автоматических проверок, результаты, матрица трассировки |

Нотации: BPMN 2.0 для процессов; UML (диаграммы последовательности и состояний) и ER-диаграмма в Mermaid, отрисовываются прямо на GitHub; критерии приёмки в Gherkin.
