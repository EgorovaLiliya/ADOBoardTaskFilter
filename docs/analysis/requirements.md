# Требования

Версия продукта: 1.0.0.

## 1. Контекст и проблема

Команда ведёт работу на канбан-доске Azure DevOps Server. На доске карточки PBI и Bug. Ответственного за карточку указывают в поле Assigned To или в пользовательском поле вида «Ответственный», обычно это владелец продукта, аналитик или ведущий разработчик. Разработчики и тестировщики работают в дочерних Task.

Встроенный фильтр доски отбирает карточки по полям самих карточек. На вопрос «над чем сейчас работает конкретный разработчик» он не отвечает, если разработчик назначен только на Task. Ведущий встречи открывает карточки по одной и выписывает, где есть задачи нужного человека. На доске из нескольких десятков карточек это долго, и карточку легко пропустить.

## 2. Цель и критерии успеха

Цель: показать на доске работу одного или нескольких участников одним действием, не открывая карточки.

| ID | Критерий успеха |
|---|---|
| КУ-1 | После выбора участников на доске видны все карточки, где участвует хотя бы один из них, и только они |
| КУ-2 | Колонки, дорожки, перетаскивание и встроенные фильтры доски работают как без расширения |
| КУ-3 | Расширение не меняет данные на сервере и не требует прав сверх чтения рабочих элементов |
| КУ-4 | Расширение подключается к любому серверу Azure DevOps Server без правки кода и без изменений на сервере |
| КУ-5 | Расширение получает доступ только к серверам, которые пользователь добавил сам |

## 3. Границы решения

В рамках:

- канбан-доски Azure DevOps Server 2020 и новее с REST API 6.0;
- карточки любых типов, которые отображаются на доске;
- прямые дочерние элементы настраиваемых типов (по умолчанию Task);
- отбор карточек в браузере пользователя;
- настройка серверов и правил отбора на странице настроек.

Вне рамок:

- изменение рабочих элементов;
- доска задач спринта (Taskboard) и списки бэклога;
- Azure DevOps Services (облачная версия);
- отчёты о загрузке участников;
- публикация в Chrome Web Store.

## 4. Заинтересованные лица и роли

| Роль | Интерес | Как использует решение |
|---|---|---|
| Ведущий командной встречи (скрам-мастер, тимлид) | Провести ежедневную встречу по участникам | Выбирает участника и обсуждает его карточки |
| Участник команды (разработчик, тестировщик) | Найти свои карточки на общей доске | Выбирает себя в списке, расширение запоминает выбор |
| Владелец продукта, руководитель | Видеть загрузку участника или пары участников | Выбирает нескольких людей, выключает «Только незавершённые задачи», чтобы увидеть и завершённую работу |
| Администратор Azure DevOps | Безопасность и нагрузка на сервер | Проверяет, что расширение только читает данные и обращается к серверу пакетами |
| Пользователь, который настраивает расширение | Подключить свой сервер и свой процесс | Добавляет сервер, задаёт типы дочерних элементов и завершённые состояния |

## 5. Пользовательские истории и критерии приёмки

Примеры используют данные стенда: карточки 101–105 и дочерние элементы 201–205 (см. [Проверка](testing.md)).

### US-01. Отбор по исполнителю

Как ведущий ежедневной встречи, я хочу выбрать участника и увидеть на доске только карточки с его участием, чтобы обсуждать работу человека, не открывая карточки.

```gherkin
Сценарий: участие через дочернюю Task
  Дано карточка PBI 103 назначена на Owner A
  И у PBI 103 есть дочерняя Task 203 в состоянии Active, назначенная на Dev C
  Когда я выбираю «Dev C» в списке людей
  Тогда карточка PBI 103 остаётся на доске
  И карточки без участия Dev C скрыты
  И в строке состояния выводится «Показано 1 из 4»
```

### US-02. Несколько участников

Как руководитель, я хочу выбрать нескольких людей сразу, чтобы видеть общую работу пары или подгруппы.

```gherkin
Сценарий: карточки любого из выбранных
  Дано выбран «Analyst D»
  Когда я дополнительно выбираю «Dev C»
  Тогда на доске видны карточки 102 и 103
```

### US-03. Участие через поля карточки

Как владелец продукта, я хочу, чтобы учитывались поля самой карточки, чтобы видеть карточки, где человек отвечает за результат, даже если на него нет задач.

```gherkin
Сценарий: пользовательское и многозначное поле типа Identity
  Дано в карточке PBI 102 поле «Ответственный» содержит Analyst D, а поле «Ревьюеры» содержит QA E
  Когда я выбираю «Analyst D» или «QA E»
  Тогда карточка PBI 102 остаётся на доске

Сценарий: поля истории не учитываются
  Дано карточку Bug 104 создал Dev B, других связей с Dev B у неё нет
  Когда я выбираю «Dev B»
  Тогда карточка Bug 104 скрыта
```

### US-04. Только незавершённые задачи

Как ведущий встречи, я хочу по умолчанию не учитывать завершённые задачи, чтобы видеть текущую работу, а не историю.

```gherkin
Сценарий: закрытая Task не делает карточку видимой
  Дано у PBI 101 есть дочерняя Task 202 в состоянии Closed, назначенная на Dev C
  И включено «Только незавершённые задачи»
  Когда я выбираю «Dev C»
  Тогда карточка PBI 101 скрыта

Сценарий: выключенный переключатель учитывает завершённые задачи
  Дано выбран «Dev C»
  Когда я выключаю «Только незавершённые задачи»
  Тогда видны карточки PBI 101 и PBI 103
```

### US-05. Поиск в списке людей

Как участник большой команды, я хочу найти человека по части имени, чтобы не листать длинный список.

```gherkin
Сценарий: поиск по подстроке
  Когда я ввожу «dev» в поле «Найти человека»
  Тогда в списке остаются только Dev B и Dev C
```

### US-06. Актуальные данные

Как участник встречи, я хочу, чтобы новые карточки и изменения учитывались без перезагрузки страницы, чтобы фильтр не врал во время встречи.

```gherkin
Сценарий: новая карточка на доске
  Дано выбран «Dev C»
  Когда на доске появляется карточка PBI 105, назначенная на Dev C
  Тогда расширение загружает данные только по карточке 105
  И карточка 105 остаётся на доске
  И в строке состояния выводится «Показано 2 из 5»

Сценарий: ручное обновление
  Дано выбран «Dev C»
  Когда я нажимаю кнопку обновления
  Тогда данные загружаются заново, выбор и отбор сохраняются
```

### US-07. Сброс без вреда встроенному фильтру

Как участник, я хочу снять выбор одной кнопкой и не потерять действие встроенного фильтра доски.

```gherkin
Сценарий: сброс возвращает карточки, скрытые расширением
  Дано выбраны люди и часть карточек скрыта
  Когда я нажимаю «Сбросить»
  Тогда карточки, скрытые расширением, снова видны

Сценарий: сброс не отменяет встроенный фильтр
  Дано карточку скрыл встроенный фильтр доски
  Когда я выбираю людей, а затем нажимаю «Сбросить»
  Тогда карточка остаётся скрытой

Сценарий: счётчик видит только доступные карточки
  Дано встроенный фильтр скрыл карточку PBI 103
  Когда я выбираю «Dev C»
  Тогда в строке состояния выводится «Показано 0 из 3»
```

### US-08. Устойчивость к перерисовке и смене доски

Как участник, я хочу, чтобы отбор сохранялся при перерисовке доски и корректно сбрасывался при переходе на другую доску.

```gherkin
Сценарий: перерисовка карточки
  Дано выбран «Dev C» и карточка PBI 101 скрыта
  Когда доска заново отрисовывает карточку PBI 101
  Тогда карточка снова скрыта
  И раскладка доски не пересчитывается, если набор скрытых карточек не изменился

Сценарий: переход на другую доску
  Дано выбран «Owner A» на доске Team
  Когда я перехожу на доску Team2 без перезагрузки страницы
  Тогда расширение загружает данные новой доски
  И выбор доски Team на доску Team2 не переносится
```

### US-09. Запоминание выбора

Как участник, я хочу, чтобы расширение помнило мой выбор для каждой доски, чтобы не выбирать себя каждое утро.

```gherkin
Сценарий: перезагрузка страницы
  Дано на доске выбран «Owner A»
  Когда я перезагружаю страницу
  Тогда «Owner A» снова выбран и отбор применён
```

### US-10. Подключение своего сервера

Как пользователь, я хочу добавить свой сервер Azure DevOps по адресу или ссылке на доску, чтобы расширение работало у меня без правки кода.

```gherkin
Сценарий: добавление по ссылке на доску
  Когда я ввожу ado.company.ru/tfs/Coll/Proj/_boards/board/t/Team/Stories и нажимаю «Добавить»
  Тогда браузер запрашивает доступ к https://ado.company.ru
  И после согласия сервер отображается в списке с пометкой «доступ есть»

Сценарий: доступ не выдан
  Когда я добавляю сервер и отказываю в доступе
  Тогда сервер отображается с пометкой «нет доступа» и кнопкой «Выдать доступ»
  И скрипт расширения на страницы этого сервера не встраивается
```

### US-11. Настройка правил отбора

Как пользователь со своим процессом, я хочу задать типы дочерних элементов, завершённые состояния и поля, которые не считаются участием.

```gherkin
Сценарий: дочерние Task и Bug
  Дано в настройках указаны типы дочерних элементов Task и Bug
  И у PBI 103 есть дочерний Bug 205, назначенный на QA E
  Когда я выбираю «QA E»
  Тогда видны карточки PBI 102 и PBI 103
```

### US-12. Удобная панель

Как участник, я хочу свернуть панель, выбрать её сторону и тему, чтобы она не мешала работе с доской.

```gherkin
Сценарий: свёрнутая панель
  Дано выбран «Dev C»
  Когда я сворачиваю панель
  Тогда отбор продолжает действовать
  И на свёрнутой кнопке видно «Dev C» и «2/5»
```

## 6. Сценарий использования UC-01 «Отобрать карточки по участникам»

Основное действующее лицо: участник команды.

Предусловия: сервер добавлен на странице настроек, доступ к нему выдан; пользователь вошёл в Azure DevOps в этом браузере.

Гарантия успеха: на доске видны только карточки, где участвует хотя бы один выбранный человек.

Основной поток:

1. Пользователь открывает канбан-доску.
2. Система показывает панель со статусом «Жду карточки на доске…» и ждёт карточки до 15 с.
3. Система определяет номера карточек по разметке доски.
4. Система загружает поля карточек, связи с дочерними элементами и поля дочерних элементов через REST API.
5. Система показывает список людей с числом карточек каждого и восстанавливает сохранённый выбор.
6. Пользователь выбирает одного или нескольких людей.
7. Система скрывает карточки без их участия и выводит «Показано N из M».
8. Пользователь работает с доской. При перерисовке система повторно применяет отбор, новые карточки дозагружает.
9. Пользователь нажимает «Сбросить». Система возвращает скрытые ею карточки.

Альтернативные потоки:

- 6а. Пользователь ищет человека по части имени. Система сужает список.
- 6б. Пользователь выключает «Только незавершённые задачи». Система пересчитывает список и отбор.
- 8а. Пользователь нажимает кнопку обновления. Система выполняет шаги 3–5, сохраняя выбор.
- 8б. Пользователь переходит на другую доску. Система выполняет шаги 2–5 для новой доски.

Исключения:

- 2а. Карточки не появились за 15 с. Система выводит «Карточки не найдены…».
- 4а. Сервер вернул ошибку или не ответил за 20 с. Система выводит понятное сообщение и не строит список.

| FR-02 | Скрипт расширения встраивается только в страницы досок (`/_boards/`, `/_backlogs/`) серверов с выданным доступом | US-10 |
| FR-03 | Удаление сервера отзывает доступ, если он не нужен другому серверу из списка | US-10 |

| FR-05 | Номер карточки определяется по селектору номера, затем по ссылке на рабочий элемент внутри карточки, затем по атрибуту данных. Селекторы карточки и номера настраиваются | US-11 |
| FR-06 | Базовый адрес REST API определяется по адресу страницы: путь до раздела `_boards` или `_backlogs` | US-10 |

| FR-10 | Участником карточки считается любое значение поля типа Identity, включая многозначные поля, кроме полей из списка исключений | US-03 |
| FR-11 | Список людей содержит всех участников карточек на доске с числом карточек каждого, упорядочен по алфавиту, поддерживает поиск по подстроке | US-01, US-05 |

| FR-14 | Карточки скрываются классом встроенного фильтра доски с отметкой расширения. Раскладка доски пересчитывается, только если изменился набор скрытых карточек | US-08 |
| FR-15 | Расширение реагирует только на появление и исчезновение карточек. Изменения в самой панели и в атрибутах карточек не запускают пересчёт | US-08 |
| FR-16 | Новые карточки видны, пока по ним нет данных, и дозагружаются отдельными запросами | US-06 |
| FR-17 | Кнопка обновления заново загружает данные и сохраняет выбор | US-06 |
| FR-18 | Сброс возвращает только карточки с отметкой расширения. Счётчики не учитывают карточки, скрытые встроенным фильтром | US-07 |
| FR-19 | При смене доски без перезагрузки страницы данные загружаются заново, выбор восстанавливается для новой доски. Вне досок панель скрыта | US-08 |
| FR-20 | Выбор и режим «Только незавершённые задачи» запоминаются для каждой доски, если включено в настройках | US-09 |
| FR-21 | Автообновление данных с заданным интервалом, только пока вкладка видна | US-06 |

## 8. Нефункциональные требования

| ID | Категория | Требование |
|---|---|---|
| NFR-01 | Безопасность | Расширение не запрашивает доступ к сайтам при установке. Доступ выдаётся на каждый сервер отдельно |
| NFR-02 | Безопасность | Только запросы на чтение (`workitemsbatch`, `wiql`), без изменения рабочих элементов |
| NFR-03 | Безопасность | Аутентификация через текущую сессию браузера, учётные данные и токены не запрашиваются и не хранятся |
| NFR-04 | Конфиденциальность | Данные рабочих элементов не сохраняются и не передаются третьим сторонам. В браузере хранятся только настройки и выбранные люди |
| NFR-05 | Производительность | Загрузка доски из N карточек с T дочерними элементами: ⌈N/200⌉ + ⌈N/100⌉ + ⌈T/200⌉ запросов. Смена выбора запросов не требует. В простое расширение не выполняет работы |
| NFR-06 | Надёжность | Тайм-аут запроса 20 с. Ответы устаревших загрузок отбрасываются |
| NFR-07 | Совместимость | Chromium 102 и новее с Manifest V3; Azure DevOps Server 2020 и новее; адреса с префиксом `/tfs/` и без него |
| NFR-08 | Удобство | Панель шириной 296 px, сворачивается, есть светлая и тёмная тема, управление с клавиатуры |
| NFR-09 | Изоляция | Панель живёт в Shadow DOM: стили доски её не задевают, её стили не задевают доску |
| NFR-10 | Сопровождаемость | Модули по ответственности: настройки, клиент API, модель данных, работа с разметкой, панель, контроллер |

## 9. Ограничения, допущения и риски

| ID | Тип | Описание | Мера |
|---|---|---|---|
| О-1 | Ограничение | Карточки находятся по CSS-классам доски. По умолчанию `.board-tile` и `.id-title-container .id` | Селекторы настраиваются; номер ищется ещё по ссылке на рабочий элемент |
